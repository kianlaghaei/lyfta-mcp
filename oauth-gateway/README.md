# Personal Lyfta MCP — ChatGPT OAuth Gateway

This is a **second** Cloudflare Worker for ChatGPT OAuth authentication. It does not replace the original `worker/` Lyfta MCP server, its 12 tools, or the Lyfta API.

## Architecture

ChatGPT (OAuth 2.1, authorization code with PKCE)
 -> `lyfta-personal-oauth` (owner-only login/consent and OAuth tokens in Cloudflare KV)
 -> internal Cloudflare Service Binding `LYFTA_WORKER`
 -> `lyfta-personal-mcp` (existing independent bearer protection)
 -> official Lyfta Community API.

Upstream service is still protected by its own token; the gateway must have the identical `MCP_ACCESS_TOKEN` secret and the original server must have a **separate** `LYFTA_API_KEY` secret.

The OAuth KV namespace was created under the account on 2026-11-15; it stores OAuth client registrations/grants/tokens, not Lyfta training logs. This is the minimal persistent state OAuth requires.

Deploy the **main** Worker first (directory `worker/`), then the OAuth Gateway. Owner supplies two strong distinct secrets securely via interactive Wrangler:

```powershell
# inside worker/
npx wrangler secret put LYFTA_API_KEY
npx wrangler secret put MCP_ACCESS_TOKEN
npm run deploy

# inside oauth-gateway/
npx wrangler secret put OAUTH_OWNER_PASSWORD
npx wrangler secret put MCP_ACCESS_TOKEN
npm run deploy
```

`MCP_ACCESS_TOKEN` must match across the two Workers, be at least 32 strong random characters, and must NOT equal the Lyfta API key. `OAUTH_OWNER_PASSWORD` is a separate strong random password (at least 16 characters, with 20 generated by the rotation script) entered on the owner consent page. Do not send secrets in chat, source code, logs or screenshots.

For a one-time automated provisioning of the matching Worker-to-Worker token and a strong owner OAuth passphrase **after both Workers exist**, run on the Windows owner machine:

```powershell
cd C:\Users\k.laghaei\Projects\lyfta-mcp\oauth-gateway
powershell -NoProfile -File scripts\provision-secrets.ps1
```

The initial script securely generates separate 384-bit credentials, installs them as Cloudflare Secrets, and backs them up as current-user DPAPI-encrypted SecureStrings in `$env:APPDATA\LyftaMCP\owner-secrets.dpapi.clixml`. It refuses to rotate an existing secret backup. To copy your OAuth owner passphrase to the local clipboard for ChatGPT's browser consent page:

```powershell

```

A simpler owner password can be generated and securely rotated at any time with:

```powershell

```

It produces a 20-character strong password using an unambiguous alphanumeric alphabet, uploads it directly as a Cloudflare secret, and updates the current-user DPAPI backup. It does not change the Lyfta API key or the independent internal MCP credential.

Never commit, share, or screenshot the clipboard value. The setup of `LYFTA_API_KEY` remains a separate owner-only action.

## Security / limitations

- The owner's password is compared to the secret using SHA-256 digests; it is not an email or identity-provider login. Use a random high-entropy secret and do not share it.
- OAuth Provider v1 manages OAuth 2.1 PKCE, consent CSRF cookie, client registration, token grants and expirations in KV.
- The page displays client name, verified/claimed identity, redirect host and requested scopes before the owner approves.
- ChatGPT initially requests **both** `mcp:read` and `mcp:write` through the protected-resource metadata. Read tools require `mcp:read`; create tools require `mcp:write`. Main MCP also requires explicit confirmed preview receipts for writes. Existing read-only authorizations must be disconnected/re-authorized after a scope update.
- Static bearer clients can still connect directly to the original Worker, if enabled and securely configured.
- A random owner password has no 2FA. If broader exposure or shared users are desired later, replace this with an established identity provider and add abuse rate-limiting.
- No live ChatGPT linking, Lyfta read, or Lyfta write has yet been validated.
- Never deploy with dummy test credentials; never remove upstream bearer checks.
